# Local Supabase development

Ledger uses Supabase CLI 3.1.0 (pinned in `package-lock.json`) and Docker Desktop to run a local PostgreSQL 17, Auth, PostgREST, Studio, and supporting services. Local settings are in `supabase/config.toml`; the app's ignored `.env.local` uses `http://127.0.0.1:54321` and local-only keys generated by the CLI. The npm scripts also locate Docker Desktop's per-user Windows installation when its CLI is missing from `PATH`.

## Prerequisites and commands

Install and start Docker Desktop, then open a fresh PowerShell in the repository. The npm scripts invoke the pinned local CLI without a global install:

```powershell
npm run supabase:version
npm run supabase:local:start
npm run supabase:local:status
npm run supabase:local:stop
npm run supabase:local:reset
npm run supabase:local:migration-list
npm run supabase:local:types
```

`start` downloads any missing local container images. `status` prints local service URLs, keys, and database connection details. `stop` stops only this project's local containers; it preserves their local database volume.

Useful local endpoints are PostgreSQL at `127.0.0.1:54322`, Supabase API/PostgREST at `http://127.0.0.1:54321`, Studio at `http://127.0.0.1:54323`, and the local email inbox at `http://127.0.0.1:54324`.

## Health checks

With the stack running, `npm run supabase:local:status` should report healthy services. Check PostgreSQL directly with `psql "postgresql://postgres:postgres@127.0.0.1:54322/postgres" -c "select current_database(), version();"` if `psql` is installed. Check Auth with `Invoke-RestMethod http://127.0.0.1:54321/auth/v1/health`, and PostgREST with `Invoke-WebRequest http://127.0.0.1:54321/rest/v1/ -Headers @{ apikey = '<local-anon-key>' }`. A healthy API should answer; Auth is configured locally with email confirmations disabled for development.

`supabase:local:types` writes current local schema types to `lib/supabase/database.types.ts`. After resetting or changing migrations, rerun it to keep types in sync. Never put a hosted key in `.env.local`.

## Migrations

Apply the tracked migrations to the local database with:

```powershell
npm run supabase:local:reset
```

This script calls `supabase db reset` without `--remote`: it drops and recreates **the local database only**, then applies local migrations in timestamp order. The timestamped foundation migration creates the required base schema; the following feature migrations add the Ledger functionality. A clean local reset has been executed successfully and all migration versions are present in `supabase_migrations.schema_migrations`.

The local reset script explicitly unsets `SUPABASE_DB_PASSWORD` and `SUPABASE_ACCESS_TOKEN` for the CLI invocation and does not pass any remote flag. `supabase migration list` defaults to local and no remote is linked. Do not use `supabase link`, `supabase db push`, or `--remote` when working through these local scripts. The project identifier in `config.toml` is not a remote connection setting.

The existing feature migrations retain their order. See `supabase/migrations/README.md` for the sequence and scope. `lib/supabase/schema.sql` remains an archival, non-executable snapshot and is not the baseline.
